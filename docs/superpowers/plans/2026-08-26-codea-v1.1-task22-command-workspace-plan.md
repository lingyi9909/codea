## Boundaries

- Keep the existing Codea-owned `AgentRuntime` abstraction unchanged.
- Do not implement Task 23 model/compaction/runtime expansion.
- Do not implement Task 24 professional built-in routing.
- Preserve Windows, pure-intranet, DLP, approval, and OpenCode v1.18.11 behavior.
- Do not copy OpenCode/Claude Code TUI; add only the approved command workspace.

## Implementation sequence

1. Add RED tests for a terminal-independent command registry/parser/executor, deterministic conflict errors, custom Markdown loading, and template argument expansion.
2. Add RED application tests for palette open/filter/navigation/modal isolation, direct command execution, and unknown slash-command model isolation.
3. Implement `tui/internal/command` with built-in definitions, parser, structured outcomes, priority-preserving registry, and fail-closed Markdown loaders for enterprise/project scopes.
4. Integrate the registry into the composition root and Bubble Tea model without leaking runtime-vendor types.
5. Add the palette overlay and keyboard routing. Existing shortcuts remain active when the palette is closed.
6. Reuse existing application/runtime capabilities for the Task 22 built-ins where already available; defer Task 23-specific runtime workspace semantics.
7. Run Task 22 gates on Linux and Windows, then full Go regression/vet/build and Windows cross-build.
8. Record Task 22 verification and set execution state to `awaiting_acceptance`; do not start Task 23 before human acceptance.

## Acceptance mapping

- `/` opens palette: application keyboard test.
- live filtering + arrows + Enter/Esc: palette tests.
- direct full command: application command-submit test.
- unknown command never reaches model: fake-runtime regression.
- palette input isolation: modal keyboard regression.
- enterprise/project Markdown load: command loader tests.
- conflict fail-closed: registry priority/collision tests with `COMMAND_CONFLICT`.
- shortcut/general chat regression: existing application test suite + full Go regression.
