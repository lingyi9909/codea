# Task 24 Professional Agent Workspace Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver deterministic professional Agent commands, session-safe active-Agent switching, and a first-class controlled Debug Agent/Skill without duplicating the existing Reviewer, Unit Test, or API Documentation Agents.

**Architecture:** Reuse the Task 22 `CommandRegistry` and Task 23 application/session workspace. Professional built-ins are `OutcomePrompt` routes whose fixed `Definition.Agent` is copied directly into Codea-owned `runtime.PromptRequest.Agent`; `/agents` becomes a Codea-owned picker for multi-turn Agent selection. Debug is added as distribution metadata/prompt/Skill and is materialized by the existing Agent materializer; read-only tools are allowed while mutation/command tools use `ask` so existing approval, command policy, DLP, and path controls remain authoritative.

**Tech Stack:** Go 1.26.5, Bubble Tea, Codea AgentRuntime contract, OpenCode v1.18.11, Markdown/YAML distribution artifacts, GitHub Actions Windows/Linux gates.

**Spec:** `docs/superpowers/specs/2026-08-26-codea-v1.1-agent-workspace-design.md` §24

## Global Constraints

- Keep `TUI → Application → Codea-owned AgentRuntime Contract → OpenCodeAdapter → OpenCode v1.18.11`.
- OpenCode remains pinned to `v1.18.11`.
- Windows 10/11 x64 and pure-intranet operation remain supported; no WSL dependency.
- Preserve DLP, Approval, Tool Policy, path policy, and offline constraints.
- Vendor DTOs must not cross into Application/TUI.
- Do not introduce a second Runtime abstraction.
- Do not copy the existing `code-reviewer`, `unit-test-generator`, or `api-documentation` prompts/Skills/policies into the command layer.
- Professional commands never route through General Agent.
- Do not implement Task 25 Live Trace/conversation redesign in Task 24.
- Direct commits to `develop`; never force push.
