Scope: Task 23 only

## Goal

Expose real Runtime model/session/compaction/status/doctor capabilities through the Task 22 Command Workspace while preserving the Codea-owned `AgentRuntime` boundary and OpenCode v1.18.11 adapter isolation.

## Architecture decisions

- Extend `AgentRuntime` only with Codea-owned `ListModels` and `CompactSession` capabilities.
- Reuse existing `PromptRequest.Model`; do not add a vendor-style SetModel method.
- Keep selected model as application session state; a new session starts with no explicit model and therefore uses the Runtime configured/default model.
- `/model` reads real Runtime models and writes only current-session selection; subsequent prompts carry that `ModelRef`.
- `/compact` invokes real current-session compaction. OpenCode adapter resolves the real model needed by v1.18.11 summarize from the current session/model history; no fake clear/history deletion/session replacement.
- Reuse existing `ContextCompaction` capability flag and fail closed when unsupported.
- `/doctor` and CLI doctor share `internal/doctor.Service`; TUI must not implement a second health-only doctor workflow.
- `/status` presents sanitized Codea-owned context only; never API keys, raw provider options, or vendor DTOs.
- Session resume/switch keeps model selection isolated by session and resets transient streaming/reasoning/tool UI state.

## Implementation sequence

1. Record Task 22 human acceptance and Task 23 `in_progress` execution state.
2. Add RED contract/adapter tests for `Model`, `ListModels`, and real `CompactSession` against the OpenCode v1.18.11 HTTP shapes.
3. Implement OpenCode model listing from `/provider`, mapping only connected/runtime-available providers into Codea-owned models; keep default metadata only where needed by adapter logic.
4. Implement OpenCode real compaction through `POST /session/:id/summarize`, resolving provider/model from current session messages/model state and returning typed Runtime errors on unsupported/invalid state.
5. Add RED application tests for `/model` modal selection, per-session isolation, selected-model prompt application, new-session default behavior, and `/compact` capability/error handling.
6. Register Task 23 built-ins `/model` and `/compact` through the existing Command Registry; add model picker UI without creating a second command system.
7. Upgrade `/status` to the approved sanitized Runtime/session/agent/model/skill/capability view.
8. Inject the existing Doctor service/use-case into the TUI so `/doctor` executes the same service contract used by CLI `codea doctor`.
9. Add regressions for session resume transient-state reset and model isolation.
10. Add Task 23 Linux/Windows Gates including execution-state validation, focused Runtime/Application tests, full Go regression, vet/build, Windows cross-build, OpenCode adapter tests, and architecture vendor-leakage checks.

## Acceptance mapping

- `/model` lists real Runtime models.
- Model selection is current-session only.
- Subsequent `PromptRequest.Model` uses the selected model.
- A newly created session does not inherit another session's explicit model.
- `/compact` performs real same-session Runtime compaction.
- Unsupported compaction fails explicitly and never clears history/creates a session.
- `/status` includes approved context/capability fields without secrets.
- `/doctor` and CLI share `doctor.Service`.
- Session resume does not retain stale streaming/reasoning/tool transient state.
- No OpenCode DTO leaks above adapter; OpenCode v1.18.11 adapter remains green.
