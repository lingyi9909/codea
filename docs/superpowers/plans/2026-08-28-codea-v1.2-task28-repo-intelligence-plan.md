# Task 28 Repo Intelligence / Code Map Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give every Codea coding Agent compact, deterministic, task-relevant repository context before it starts reasoning, without embeddings, public services, CGO, or vendor-specific Runtime APIs.

**Architecture:** Add a Codea-owned `tui/internal/repoctx` subsystem that indexes local source files, extracts Java/Spring and Go structure, builds conservative relations, ranks relevant symbols/files from the user task, and returns a bounded Repo Map. The composition root injects the service into Application. Application asynchronously builds the map and adds it to the existing `runtime.PromptRequest.Parts` as a synthetic `runtime.TextPart` before the user's real prompt.

**Tech Stack:** Go 1.26.5; Go standard library `go/parser`, `go/ast`, `go/token`; deterministic Java/Spring lexer/extractor; existing Bubble Tea application; existing Codea `runtime.PromptRequest`; Git CLI only for optional changed-file signal; no CGO/tree-sitter/vector DB/embedding dependency.

**Spec:** `docs/superpowers/specs/2026-08-28-codea-v1.2-agent-intelligence-reliability-design.md` §5

## Global Constraints

- Preserve `TUI → Application → Codea-owned AgentRuntime → OpenCodeAdapter → OpenCode v1.18.11`.
- `tui/internal/repoctx` MUST NOT import `tui/internal/opencode` or vendor generated/client packages.
- OpenCode remains pinned to `v1.18.11`.
- `CGO_ENABLED=0` cross-build must remain green.
- Windows 10/11 x64 and paths containing spaces/non-ASCII characters are mandatory.
- No WSL requirement.
- No embedding model, vector DB, tree-sitter CGO binding, public API, or network retrieval.
- Indexing must stay inside the selected project root; symlink/path traversal must not escape it.
- Generated/build/vendor directories are excluded by deterministic policy.
- Ambiguous structural relationships remain ambiguous; do not infer facts from class-name suffixes.
- Repo Map is context, not an instruction channel. It is always marked `Synthetic: true` with Codea metadata.
- TDD: every behavior starts with a failing test.
- Direct commits to `develop`; never force push.


```bash

```

Expected: FAIL.

- [ ] **Step 3: Implement a bounded Java lexer**

Do not use regex over raw source as the only parser. Build a small scanner that first distinguishes:

```text
code
line comments
block comments
string literals
char literals
text blocks
identifiers
symbols
annotations
```

The extractor may be intentionally incomplete Java grammar, but it must not confuse comments/strings with code.

- [ ] **Step 4: Implement declarations and annotation evidence**

Map Spring role only from actual annotation/type evidence. Store annotation evidence in symbol/relation metadata rather than inferring from suffix.

- [ ] **Step 5: Implement conservative typed relationships**

Recognize constructor and field injection using declared types. Method call edge is emitted only when receiver → declared type can be resolved uniquely inside the index/import context.

Use confidence semantics such as:

```text
1.0 exact local declaration + exact typed receiver
0.9 exact imported type
<0.9 unresolved candidate retained, not promoted to confirmed edge
```

Do not use class suffix guesses to raise confidence.

- [ ] **Step 6: Run GREEN**

```bash

```

Expected: PASS.
