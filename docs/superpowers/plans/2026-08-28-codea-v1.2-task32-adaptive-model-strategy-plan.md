# Task 32 Model Qualification & Adaptive Agent Strategy Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Measure whether the configured private model can reliably operate Codea's Agent protocol, persist a conservative machine capability profile, and adapt Repo Context, planning strictness, and verification repair budget so weaker models receive tighter execution support instead of simply failing.

**Architecture:** Add four deterministic non-mutating probe tools and a tightly permissioned `model-evaluator` utility Agent. `/model-check` runs a bounded qualification task using the actual selected `runtime.ModelRef`; Application observes probe lifecycle events and scores first-attempt/retry behavior without parsing chain-of-thought. Profiles persist locally under CODEA_HOME. Normal prompt preparation resolves the selected/default model profile and injects a synthetic Codea `model-strategy` part; the same strategy supplies Task 28 Repo Map budget and Task 30 repair-continuation budget. Security permissions never expand from a stronger score.

**Tech Stack:** Go 1.26.5, existing Codea AgentRuntime/session/model APIs, Bun 1.3.14 plugin probes, existing Agent materialization/CommandRegistry/Live Trace, atomic JSON profile storage.

**Spec:** `docs/superpowers/specs/2026-08-28-codea-v1.2-agent-intelligence-reliability-design.md` §9

## Global Constraints

- No external benchmark service, public API, telemetry upload, or internet dependency.
- Qualification never edits project files and never runs project bash/commands.
- The model does not self-report its capability score.
- Machine score is derived only from observed bounded probe tool outcomes/attempt order.
- Unknown/unqualified model defaults to conservative `medium` strategy.
- Profile affects context/autonomy/retry behavior only.
- Profile MUST NOT grant tools, bypass approval, weaken DLP/path/command policy, enable public network, or override Agent permissions.
- A strong score cannot make a denied action allowed.
- Probe Agent is a utility Agent only; do not add new business/professional Agents.
- Probe sessions/events must not pollute the user's visible conversation or active Agent selection.
- Existing model selection remains session-scoped.
- OpenCode remains pinned to v1.18.11; no vendor DTO enters Application.
- Windows 10/11 x64, no WSL.
- TDD and bounded attempts.
- Direct commits to `develop`; never force push.
