# Task 31 Agent Checkpoint & Restore Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give Codea Agents safe, local, reversible project snapshots so complex private-model edits can be attempted without relying on the user's project Git branch/index or on model memory.

**Architecture:** Add a Codea-owned Go `checkpoint` subsystem that maintains a shadow Git object/index store under CODEA_HOME and uses the user's project only as a work tree. Checkpoints are created asynchronously before Agent prompts, after verified completion, and immediately before restore. The shadow repository has its own Git dir/index/refs; project `.git` branch/index/refs are never touched. Existing CommandRegistry adds deterministic `/checkpoint`, `/checkpoints`, and `/restore <id>` workspace actions without routing through an LLM.

**Tech Stack:** Go 1.26.5, Git CLI via fixed argv/explicit `--git-dir` + `--work-tree`, existing Bubble Tea command/application architecture, Codea Home local storage, existing CommandRegistry.

**Spec:** `docs/superpowers/specs/2026-08-28-codea-v1.2-agent-intelligence-reliability-design.md` §8

## Global Constraints

- Shadow checkpoints MUST NOT create commits, refs, branches, stash entries, or index changes in project `.git`.
- Do not implement rollback by calling `git reset --hard` against the user's project repository.
- Git commands use argv only; no shell interpolation.
- Shadow storage is local under CODEA_HOME and must not require network.
- Project paths with spaces/non-ASCII characters must work.
- Windows 10/11 x64, no WSL.
- Checkpoint creation runs outside Bubble Tea `Update`.
- Restore is blocked during streaming or pending approval.
- A safety checkpoint is mandatory immediately before restore.
- If checkpointing is unavailable, Codea says so; it never fabricates protection.
- Checkpoint failure does not turn a valid verified code result into “verification failed”; checkpoint and verification are separate truth dimensions.
- Exclude sensitive/generated/large files from the shadow store by deterministic policy; Agent security policy remains the primary control preventing sensitive writes.
- Default retention: latest 20 checkpoint records per workspace, with protected baseline/safety records retained until their task closes.
- TDD and factual evidence only.
- Direct commits to `develop`; never force push.

## Task 31 Done Criteria

Task 31 is complete only when:

- shadow repo is outside project and uses separate index/refs;
- checkpoint create handles modify/add/delete state;
- restore is exact for eligible files;
- safety checkpoint is always created before restore;
- project branch/HEAD/index/refs are mechanically unchanged;
- busy restore is blocked;
- Repo Context invalidates after restore;
- Git unavailable degrades visibly;
- Windows native spaces/non-ASCII lifecycle passes;
- `CGO_ENABLED=0` release build and existing regressions remain green;
- human acceptance is recorded separately.
