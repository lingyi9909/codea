# Codea V1.1 Task 25 — Claude-style Conversation UX & Live Trace Implementation Plan

> Scope is fixed by `docs/superpowers/specs/2026-08-26-codea-v1.1-agent-workspace-design.md`. This plan does not re-split Task 25 and does not include Task 26 acceptance work.

## Goal

Deliver a Claude-style conversational workspace whose execution details are derived from a **Codea-owned semantic execution trace**, while preserving the existing Runtime abstraction, OpenCode adapter boundary, approval/DLP/tool-policy controls, Windows x64 behavior, and bounded streaming redraw model.

## Non-goals

- Do not clone Claude Code or OpenCode TUI.
- Do not expose Vendor DTOs in TUI/Application.
- Do not create a second Runtime/Event abstraction.
- Do not infer Agent/Skill/Plugin/Subagent names from filenames, tool names, prompts, or vendor raw payloads when structured Codea metadata is absent.
- Do not alter Task 24 professional Agent routing semantics.
- Do not perform Task 26 integration/release acceptance.

## Step 1 — Lock Codea execution-trace truth with TDD

Add focused Application tests before production changes for:

1. a prompt turn creates one Working lifecycle and one Agent trace entry using the actual `PromptRequest.Agent`;
2. repeated `tool.called` events with the same stable `Tool.CallID` update one logical trace entry rather than duplicate it;
3. the same tool name with different call IDs creates distinct invocations;
4. `tool.success` / `tool.failed` close the matching invocation by call ID;
5. approval requested creates an Approval entry in `waiting` and changes the active Working entry to `waiting`;
6. approval resolution restores Running after allow or closes/marks denied after reject when that result is known to Codea;
7. step/session/runtime terminal events close the active Working lifecycle truthfully;
8. missing structured metadata never fabricates Skill/Plugin/Subagent names.

Implementation target: a Codea-owned trace model under `tui/internal/app`, backed only by `internal/runtime.Event` and Application-known prompt state.

Stable invocation-key policy:

- turn working: `turn:<messageID>:working`
- Agent: `turn:<messageID>:agent`
- tool: `tool:<callID>` when callID exists
- approval: `approval:<approvalID>` when approval ID exists
- when a stable runtime ID is missing, allocate a Codea-local unique key and mark identity metadata as unavailable; never name-dedupe an uncertain invocation.

## Step 2 — Add `/view normal|verbose|focus`

Add a Task 25 built-in `/view` action and focused command/application tests.

Rules:

- default: `normal`
- `/view normal`: balanced semantic trace
- `/view verbose`: all available trace detail
- `/view focus`: suppress routine low-value Working/Tool trace, retain User/Assistant, approvals/blockers/failures
- invalid or missing mode produces a user-visible usage/error message without mutating trace truth
- changing view mode must not mutate, rebuild, or delete semantic trace entries

The command action may consume parsed arguments, but existing prompt-command and Task 24 Agent semantics remain unchanged.

## Step 3 — Derive Claude-style inline conversation rendering

Render semantic blocks from existing chat messages plus the Codea execution trace:

- User
- Working
- Agent
- Tool
- Skill
- Plugin
- Approval
- Assistant
- Subagent only when structured metadata is available

Truthfulness rules:

- Working appears only while active work is genuinely running; it becomes waiting during an actual approval block.
- Approval is visually explicit while blocked.
- Tool state uses queued/running/waiting/success/failed/denied as applicable.
- Skill/Plugin/Subagent labels are rendered only from structured `runtime.Event.Metadata`; if absent, do not invent a name.
- final Assistant output remains the existing conversation answer; trace must not duplicate assistant text.

## Step 4 — Preserve bounded streaming performance

Reuse the existing cached-frame + dirty flag + tick-coalesced streaming model.

- adjust the existing refresh cadence from 50ms into the design window (target 25ms, within 16–33ms);
- add a cadence contract test;
- retain existing burst tests proving N deltas do not cause N full redraws;
- trace updates remain O(1) by invocation-key index where practical; avoid rescanning an ever-growing trace for common lifecycle updates;
- session resume/reset must not leak active trace state between sessions.
