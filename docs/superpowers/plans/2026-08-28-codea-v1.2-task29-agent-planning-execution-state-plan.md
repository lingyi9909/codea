# Task 29 Agent Planning & Execution State Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make non-trivial Codea engineering work execute through an explicit bounded plan whose state is machine-observable, persistent across tool calls, visible in Live Trace, and enforced before project mutation/execution.

**Architecture:** Implement planning as a deterministic protocol, not a Planner Agent. Add `task_plan`, `task_step`, and `task_status` enterprise tools plus a plugin-owned `TaskStateStore`. The existing OpenCode plugin `tool.execute.before` hook enforces “plan before mutation/execute” for native `write`, `edit`, and `bash`; the enterprise tool adapter enforces the same for Codea write/execute tools. Application observes planning tool lifecycle and maintains a compact Codea-owned `TaskExecutionState` used later by Task 30 completion gating.

**Tech Stack:** Bun 1.3.14/TypeScript enterprise plugin, existing RuntimeSecurityGuard/OpenCode v1.18.11 plugin hooks, Go 1.26.5 Application state/Live Trace, atomic local JSON persistence under CODEA_HOME.

**Spec:** `docs/superpowers/specs/2026-08-28-codea-v1.2-agent-intelligence-reliability-design.md` §6

## Global Constraints

- No Planner LLM Agent.
- No hidden chain-of-thought persistence.
- Persist only goal/step labels/status/evidence summaries; never raw source code, prompts, secrets, command output, or credentials.
- Planning state is Codea-owned and scoped by normalized workspace + Runtime session.
- Existing DLP, Approval, command policy, path policy, and audit remain authoritative.
- Plan enforcement MUST happen before mutation/execute where the plugin has a before-hook.
- Read/grep/glob and ordinary chat remain available without a plan.
- Existing `/review` read-only flow must not be forced to create a plan.
- Existing `/test`, `/debug`, and mutation-capable General workflows must use planning before mutation/execute.
- Existing professional commands remain deterministic; no General fallback.
- Windows 10/11 x64 and no-WSL constraints remain.
- Pure intranet; no network dependency.
- TDD and bounded behavior only.
- Direct commits to `develop`; never force push.

## Task 29 Done Criteria

Task 29 is complete only when:

- plan protocol validates 3–7 steps;
- state persists atomically per workspace/session;
- native and enterprise mutation/execution is rejected before action when plan is missing;
- existing DLP/Approval still runs after plan validation;
- planning state is visible through machine telemetry without chain-of-thought leakage;
- Application derives state from allowlisted events, not assistant prose;
- read-only chat/review is not forced through unnecessary planning;
- all plugin/Go/Agent regressions are green;
- human acceptance is recorded separately.
